## 1. Why the deployable path fails although the generator realises descriptors

Facts: given the **oracle** descriptor the generator realises it (E 1.868 → 1.042, −44 %; swapped follows: 1.086 to the swapped vs 1.642 to the oracle; validity own 0 / mismatched 2.556 / ±1 s 1.768). With **retrieval** the generator again realises what it is given (0.968 to the retrieved descriptor) but that descriptor is nearly as far from GT as no token at all (1.740 vs none 1.868). So the realisation module works and the entire deployable gap is in *choosing* the descriptor. Three reasons, in order of weight:

1. **The map word → kinematics is many-to-many, and the pick is a single random sample.** The pipeline is keyword → lexicon category → BEAT2 class → sha1-random exemplar of that class. A class is a broad set (within-class descriptor variance is close to the total variance; the quick check below measures it). Even if the class carried some information, a *random member* pays the full within-class spread: for a point error, E[‖d_sample − d_GT‖²] ≈ 2σ²_class, whereas the conditional mean would pay σ²_class. The oracle row pays only the realisation error. The retrieval row therefore sits where theory predicts: at the within-class spread, i.e. at "none".
2. **Low information in the key.** S1 found word identity weakly recoverable from motion; §7.56 found semantic timing not predictable from deployable inputs (causal AUC 0.526 < shuffle 0.571) and pair_win unmoved by text. Mutual information between the keyword (or its lexicon category) and the kinematic descriptor is small, so no deterministic word-keyed lookup can get far below the marginal spread. The realisation success shows the generator is *not* the bottleneck; the predictability of the descriptor from deployable context is.
3. **Bank construction and timing.** (a) Exemplar descriptors include the hand and the direction; a random exemplar's hand is often the hand the generator has in use, so following it costs contortion (FGD 172 vs 124) and the amplitude of class exemplars sampled uniformly is lower than that of the GT-annotated events at the same places (liveliness: wrist 0.253 vs GT 0.388); (b) 42 % of keywords have no aligned occurrence within ±1 s, so 42 % of tokens are placed at a fallback time — the token asks for a gesture where the human made none; (c) the class map (LEX2SEM) was fixed by rule, not learned.

Also: E is a *point* metric for a distributional target — the same mis-specification that hurt P1. A deployable path should be judged on (i) likelihood of the realised descriptors under the human conditional distribution and (ii) unchanged marginal statistics (FGD v2, liveliness), not only on the distance to the one GT descriptor. Point E stays as the validated row with the oracle as its ceiling.

**Pre-check that costs nothing (register before reading):** on train descriptors, the ratio of within-class to total descriptor variance per component; and a ridge / k-NN regression from the causal context (e5 of the last 5 words + the prosody of the last 2 s) to the descriptor, scored on dev by E of its prediction vs none and vs the marginal mean. If the regression's E is not below the marginal mean's E by ≥ 10 %, the deployable descriptor is unpredictable from text + audio and neither design below can fix it; the result is then "controllable given intent; intent not inferable from monologue inputs" (what §7.56 already states), and the honest deployable row is the TTS-sync oracle-free fallback (no token).

## 2. Designs (ranked)

### A (rank 1): conditional descriptor density — a causal mixture head trained on the frozen generator's inputs, sampled at inference
**Mechanism.** A small causal head φ (2-layer GRU or 2-layer causal Transformer, ≤ 1 M params) over the deployable context available at the candidate time t (e5 word embeddings of the visible words with their TTS times, the lexicon category one-hot, the 8 prosody dims of the last 2 s, the generator's last planner state as a summary of the current motion incl. which hand is busy), outputting at each word onset − 0.2 s a **mixture density** over the 16-D descriptor space plus a "no gesture" component: K = 8 diagonal Gaussians with a learned "null" weight (presence). Trained on the train split with NLL against the GT descriptor at annotated events and the null component at non-events (negatives sampled at word onsets without an event within ±0.5 s). Inference: if the null weight < 0.5, sample a descriptor from the mixture at temperature 0.7 (or take the mode as the "mean" row); the sample becomes the sem_cf token value; everything downstream (frozen enc-s0 + sem_cf ctl_ modules) unchanged. Hand resolution: the descriptor's hand component is re-sampled conditioned on the planner's free hand (the mixture is over both hands; the head sees the hand-in-use feature, so it can learn this). Default off; the oracle and retrieval rows stay as controls.
**Why it addresses §1.** It replaces a random class member by a sample from a *learned conditional* distribution: when the context is informative the mixture is narrow (E drops toward the conditional spread, half the random-pick error); when it is not, the mixture is wide and sampling preserves the marginal (so FGD v2 and liveliness stay at none's level, unlike the uniform class pick). The null component removes the 42 % fallback problem (no token where no gesture is likely). It is consistent with rows 10–12: we do not predict the *class timing* as a hard decision; we predict a density and let sampling carry the uncertainty.
**Closest prior / delta.** Mixture density networks (Bishop 1994); gesture property prediction from speech / text (Kucherenko et al. 2021 "Speech2Properties2Gestures", Ahuja / Yoon property-conditioned generation); our own class / lexicon predictors (failed as hard timing gates). Delta: the predicted object is a *kinematic descriptor density* with explicit presence, used as the value of a counterfactually trained event token on a frozen causal generator; the realisation and the prediction are decoupled, each with its own validated measure.
**Pre-registration draft.**
- Primary (prediction side, train-split fit, dev score, written before training): held-out NLL gain over the unconditional mixture (same K, no inputs) ≥ 0.3 nats / event with the recording-clustered CI excluding 0; presence AUC vs the marginal rate reported (not gated: the timing finding predicts it will be near chance).
- Primary (realisation side, generator rows on the full dev set, offline / psync / TTS-sync 0.5 s, per_clip 0–2): E(sample) < E(retrieval) by ≥ 15 % and < E(marginal sample) by ≥ 10 %, CI excluding 0; E(oracle) reported as the ceiling; swap follow kept.
- Side (audit rules): FGD v2 (i) / (ii) on the sparse plan ≤ C + δ; liveliness guard; executability 100 %; none path bitwise; pair_win only on the full dev set with its sanity rows (GT max, mismatched ≈ 0.5) and only as a secondary row.
- Controls: marginal mixture (no inputs) sampled; mixture mode vs sample (mode is expected to lower E and lower liveliness — report both); retrieval row; oracle row; TTS-sync vs psync (declared protocol rows).
**Quick lane (≤ 5 min, CPU / one 5090, no generator run).** Fit φ on train descriptors (minutes), score on dev: NLL gain vs the marginal mixture; E of mixture mean and of one sample vs none, marginal mean, marginal sample, retrieval — on the 62 oracle events of the 10 recordings and on all dev events. Kills (relative, cannot saturate: all are differences against the marginal control fitted the same way): NLL gain < 0.1 nats / event; or E(sample) not ≥ 10 % below E(marginal sample). A second 5-minute step only if it passes: feed sampled descriptors to the existing sem_cf model on the 10 recordings and read E / wrist speed ratio to none (kill: wrist speed ON / none < 0.9).
**Cost.** < 0.5 GPU-h quick; full dev rows ≈ 3 GPU-h (generation) + CPU. Frozen-base add-on (the generator and the sem_cf modules are unchanged; φ is a separate head).

### B (rank 2): set-valued event tokens with a min-over-hypotheses outcome loss ("any of these")
**Mechanism.** The sem_cf token carries a *set* of k = 4 exemplar descriptors (or the mixture parameters of A) instead of one point; the counterfactual outcome loss becomes min_j ‖d(x) − d_j‖² (multiple-choice / oracle loss) or −log of the mixture density at d(x). Training swaps the whole set counterfactually; imitation lifted as now; `--train-only ctl_`, 2000 steps, frozen enc-s0. Inference: the set from A's mixture (top-k components) or from the k nearest class exemplars; the generator realises whichever member fits its state (free hand, continuity, current amplitude).
**Why.** It attacks the *cost* side of §1.3: with a point target the generator must contort toward a random exemplar's hand and amplitude (FGD 172, liveliness fail); with a set it chooses the compatible member, so FGD and liveliness should stay near none while E to the GT is at least as good as the best single-pick strategy. It does not by itself add information about the GT descriptor (that is A's job), so it is ranked second and is most valuable combined with A.
**Closest prior / delta.** Multiple-choice learning / oracle loss (Guzman-Rivera 2012; Rupprecht 2017 multi-hypothesis prediction); set-conditioned generation. Delta: a set-valued control token with a min-loss on *decoded* kinematic descriptors inside a frozen causal generator, resolving the many-to-many word → gesture ambiguity at generation time.
**Pre-registration / quick lane.** Primary: E_set = min_j distance of the realised descriptor to the given set vs to a swapped set (follow check, relative); E to GT with sets from A vs point from A; FGD v2 / liveliness vs the point-token row (must be closer to none). Quick lane: 2000 steps ctl_-only (~4 min), 10 recordings, offline: E_set(given) < E_set(swapped) by ≥ 30 %; wrist speed ratio to none ≥ 0.9 (the point row failed this at 0.65). Kills are relative to the swapped set and to none, so they cannot saturate. Cost ≈ 0.1 GPU-h quick, 3 GPU-h full; frozen-base add-on.

## 3. Does "counterfactual event conditioning" hold as one method; what is missing

Supported, per event type, on the *mechanism* claim (a frozen causal generator follows an event token it previously ignored once the token is non-redundant, imitation is lifted and a decoded-space outcome supervises it):
- pointing: yes (STG +0.147 / +0.15 with shuffle follow; the only EX002 control design passing its gates);
- semantics: yes for realisation (E −44 % with the oracle, swap follows; −36 % under TTS-sync 0.5 s, −23.5 % under psync), **no** for the deployable source yet (retrieval ≈ none);
- yield: yes for token use (speed −43 to −62 %, LATE follows), **no** for the outcome form yet (hinge → freeze; P1b-SW pending).
So the method statement that the evidence supports today is: *counterfactual event tokens make events followable; the outcome loss must match the event's nature (point for commands, distribution for yielding and for semantic exemplars), and the deployable event source is a separate, separately validated module.* That is one method with three instances and two open parts.

Missing before it can be called a result:
1. P1b-SW (distributional yield outcome) passing M-eff / M-time and the Pareto read on the full 476 × 3 seeds; **before that, the half-A clamp finding must be resolved** — 29 % of half-A tails with exactly constant arm joints are retarget artefacts that look like freezes; they contaminated L2d's duration statistics and P1's quiet / τ sampling, and would contaminate the SW bank. The bank and the RKD reference must exclude or repair them (re-registered, A side first, then B).
2. A deployable semantic source that beats the marginal (design A), or the honest statement that the descriptor is not inferable from monologue inputs (the pre-check in §1 decides this in minutes).
3. Full-dev, 3-seed, psync + TTS-sync rows with the side gates (the 10-recording FGD 139 vs 124 is noise-level evidence either way); pair_win read only on the full dev set.
4. The three-condition ablation (swap off / flow kept / outcome off) for each event type, and the loss-form ablation (hinge vs SW) for yield.
5. Everything is EX002 dev; G1 has only the pointing instance; the test set waits for the protocol freeze.
